## 2026-03-27 - v1.2.0: External Sites Opt-in + Intentos de Transcript

### Feature: External Sites Opt-in con Whitelist
- [x] Eliminado content_script estatico `http://*/*` del manifest (bloqueaba publicacion)
- [x] Agregado `optional_host_permissions` para permisos bajo demanda
- [x] Agregado `scripting` permission para `chrome.scripting.registerContentScripts()`
- [x] Popup rediseñado con tabs: Settings | Sites
- [x] Tab "Sites": toggle enable/disable + input para agregar dominios + lista con remove
- [x] `chrome.permissions.request()` per-domain con prompt al usuario
- [x] Background registra/desregistra scripts dinamicamente
- [x] Dominios persisten en storage y se restauran al reiniciar
- [x] Deep merge en `loadSettings()` para objeto anidado `externalSites`

### Feature: Transcript Extractor (descartado - limitaciones tecnicas)
Intentos realizados y razones de fallo:
1. **Innertube `get_transcript` + protobuf**: Encoding protobuf fragil, respuestas vacias
2. **captionTracks baseUrl fetch**: URLs firmadas con IP (`ip=0.0.0.0`), devuelven 0 bytes desde content script
3. **URL limpia timedtext sin firma**: YouTube rechaza sin firma (0 bytes)
4. **MAIN world inline script**: CSP de YouTube bloquea scripts inline inyectados
5. **MAIN world manifest content script**: Error CSP persistio (posible cache, merece reintento limpio)
6. **DOM click "Show transcript"**: Click programatico no genera user gesture, panel no aparece

**Conclusion**: YouTube protege activamente el acceso a subtitulos desde extensiones. Approaches viables para futuro:
- Backend service con `youtube-transcript-api` (Python) - mas confiable
- Content script `world: "MAIN"` declarado en manifest - merece intento limpio en otra sesion

Codigo de transcript removido del bundle para v1.2. Research documentado en TODO.
